# 蜡笔 AI 投屏浏览器 PRD

> 版本：v0.4
> 日期：2026-08-10
> 状态：产品评审稿
> 产品名称：蜡笔 AI 投屏浏览器（Crayon AI Cast Browser）
> 产品平台：Windows、macOS、Linux；未来适配 HarmonyOS

## 1. 产品摘要

蜡笔 AI 投屏浏览器是一款以浏览器为交互载体、以“网页理解 + 安全投屏”为核心任务的隐私优先工作台。桌面端统一采用 Chromium/CEF，未来 HarmonyOS 采用 ArkUI/ArkWeb。用户可以把当前网页整理成结构化 Markdown、摘要或大屏阅读卡片；在主动播放网页视频后，也可以通过 Cast-SDK 把当前标签页或通过安全门禁的媒体投到自己的接收端。

产品不以替代通用浏览器为目标，也不定位为视频解析器、内容聚合器或无人值守网页机器人。核心价值是：

1. **当前页可理解**：先用确定性规则生成可追溯的结构化快照和 Markdown，再按用户选择交给模型总结或问答。
2. **网页内容可上大屏**：文章变阅读卡片，网页视频走标签页投屏或安全高清直投。
3. **隐私可感知**：默认临时会话；模型调用前展示将发送的内容、接收方和目的；遥测默认关闭。
4. **Agent 可控而非全权**：只暴露版本化工具和最小能力，页面读取与产生副作用的操作分级授权。
5. **接收端能力分层**：蜡笔接收端提供完整闭环；兼容接收端只在 Cast-SDK 明确支持且安全门禁通过时提供基础能力。
6. **公开可审计**：核心客户端、工具契约、投屏协议适配和隐私行为开源，提供可复现构建。

## 2. 背景与机会

当前仓库已完成正式 Core API v1、媒体 observation/candidate/probe/policy、受权 session relay 和 delivery 编排；旧的任意 URL 解析与 LAN proxy 已隔离到 `legacy-dev`。CEF 发行包契约和 Cast-SDK source revision 已锁定，但正式 CEF UI、Cast-SDK facade 接线、桌面采集、隐私 Profile、AI 内容管线和 Agent 工具尚未落地。

这意味着新定位不能按“从零做一个 AI 浏览器”的方式重启项目。正确路径是保留现有安全投屏主线，在 CEF 页面生命周期与 IPC 稳定后增加独立的内容快照/Markdown 领域；等安全存储、数据分级与确认 UI 可用后再接模型；最后才开放本机 CLI/MCP。这样可以先形成“当前页 -> 可读内容 -> 本机导出/大屏展示”的确定性闭环，再逐步增加 AI 与自动化。

## 3. 产品定位

### 3.1 一句话定位

> 把当前网页变成可读、可问、可投的大屏内容，并把网页视频安全投到自己的接收端。

### 3.2 核心品类

- 对外品类：AI 投屏工作台。
- 产品载体：隐私优先的 Chromium/CEF 浏览器。
- 核心任务：网页内容理解与当前页投屏。
- 差异化能力：同一上下文内完成“读取 -> 整理 -> 投屏 -> 控制”。
- 配套生态：蜡笔投屏接收端。
- 非目标品类：通用浏览器替代品、视频解析工具、影视聚合平台、下载器、无人值守 RPA、反检测指纹浏览器、批量多账号工具。

### 3.3 品牌表达

推荐表达：

- 当前网页一键整理成 Markdown。
- 发送给 AI 前先预览内容。
- 文章与视频都可以从当前页投到大屏。
- 默认无痕，浏览数据优先留在本机。
- AI 操作分级确认，随时可停。

禁止表达：

- 全网解析、VIP 解析、破解。
- 免广告、跳广告、无广告线路。
- 防封号、防关联、账号矩阵、养号。
- 完全匿名、无法追踪。
- AI 全自动替你登录、支付、上传文件或长期无人值守。
- 一键抓取全站、自动生成片库或自动识别全网剧集。

## 4. 产品原则

1. **用户主动触发**：只有用户已在当前页主动开始播放，投屏入口才进入可用状态。
2. **页面体验优先**：不得主动屏蔽、快进或跳过站点广告，不改变网站商业流程。
3. **连续观看优先**：默认从当前进度继续播放；“从头播放”由用户二次选择。
4. **不确定即降级**：无法确认广告连续性、媒体授权状态或协议兼容性时，使用标签页投屏，不进行高清直投。
5. **DRM 不碰**：不解密、不注入 CDM 绕过、不逆向许可证、不规避设备或账号限制。
6. **媒体不上云**：P0 使用 Cast-SDK 现有局域网发现、投屏码和控制能力；不把媒体、浏览数据或控制链路送入产品云端。
7. **本机最小化**：默认不保留历史、Cookie、缓存、表单、搜索词和媒体 URL。
8. **防追踪而非伪装身份**：降低指纹熵、隔离存储，不批量制造虚假设备指纹。
9. **同一产品、多个平台后端**：产品能力、协议、策略和隐私承诺统一；浏览器内核、采集、编码、安全存储和安装更新按平台适配。
10. **能力可降级、语义不降级**：平台缺少某项技术能力时，可以降级到标签页投屏或暂不支持，但不得放松 DRM、隐私和数据生命周期规则。
11. **确定性优先于模型**：正文、表格、链接、代码块和引用信息先由可测试的本地管线提取；模型不作为导出正确性或安全判断的唯一来源。
12. **页面内容始终不可信**：页面文本、DOM、无障碍树和模型输出都不能自行授予权限、取消确认、读取秘密或触发投屏。
13. **发送前可见、执行前可控**：模型调用展示数据预览；导航、输入、投屏、播放控制等副作用操作展示目标与参数并取得对应授权。
14. **工具接口不是调试后门**：不向 Agent 暴露 Cookie、Authorization、原始 CDP/WebDriver、任意 JavaScript、文件系统或通用网络代理。

## 5. 目标用户与核心任务

### 5.1 目标用户

| 用户类型 | 主要需求 | 当前痛点 |
|---|---|---|
| 家庭影音用户 | 把电脑网页视频投到电视 | 复制 URL 麻烦，接收端兼容性不确定 |
| 学习与研究用户 | 把当前文章整理成 Markdown、摘要和资料包 | 复制后结构丢失，来源难追溯，多页整理繁琐 |
| 会议与教学用户 | 把教程、提纲和网页材料快速展示到大屏 | 需要手工做幻灯片或在电视上重新打开网页 |
| 重视隐私的普通用户 | 浏览后不留下本机记录 | 主流浏览器隐私设置复杂、遥测不透明 |
| 经常使用网页播放器的用户 | 登录后直接投屏 | 独立投屏工具与浏览器登录态割裂 |
| 开源用户与开发者 | 审计隐私、AI 数据流与投屏行为 | 闭源工具无法确认网页、模型输入和设备命令去了哪里 |

### 5.2 Jobs to Be Done

- 当我在网页中开始播放内容时，我希望一键投到电视，并保持当前播放体验。
- 当我使用共享电脑浏览和登录时，我希望关闭窗口后清除本机痕迹。
- 当网站不能高清直投时，我希望产品自动选择兼容模式，而不是给出不可播放的地址。
- 当我选择接收设备时，我希望通过自动发现或投屏码快速连接蜡笔接收端并开始控制。
- 当我读完一篇网页时，我希望一键得到结构清晰、保留来源的 Markdown，而不是手工复制清理。
- 当我让 AI 总结当前页时，我希望先知道哪些内容会被发送给哪个模型，并能取消。
- 当我把文章投到电视时，我希望得到适合大屏的阅读卡片，而不是缩小的桌面网页。
- 当 Agent 要导航、输入或控制电视时，我希望看到它将做什么，并能只授权这一次。

## 6. 范围定义

### 6.1 P0 范围

- 桌面端 CEF 浏览器壳：地址栏、标签页、前进、后退、刷新、停止、页面缩放。
- 默认隐私会话。
- 用户播放状态识别。
- 当前标签页投屏。
- MP4/HLS 基础高清直投及自动降级。
- 蜡笔设备自动发现。
- 六位投屏码连接。
- 播放、暂停、继续、停止、进度同步、音量控制。
- DRM、流失效、设备不兼容提示。
- 本机 relay 会话化和访问控制。
- Windows、macOS、Linux 的安装包、签名/校验和更新能力。
- 三个平台共享同一功能契约和自动化一致性测试；具体发布日期由各自发布门禁决定。
- 当前页语义快照：只读取用户可见的主文档内容，按 navigation/generation 失效。
- 确定性正文提取与 Markdown 导出：标题、段落、列表、链接、图片引用、表格、代码块和来源信息。
- 本机复制/保存、提取预览、失败降级和引用快照；默认不上传页面正文。
- 单页摘要、要点、大纲和基于当前页的问答；只在用户配置模型并确认发送内容后启用。
- 本机阅读模式与大屏阅读卡片预览；实际投屏能力需先通过接收端/Cast-SDK capability gap 评审。

### 6.2 P1 范围

- DASH 音画双轨直投。
- 命名隐私空间/常用空间。
- 基础防追踪、第三方 Cookie 策略、HTTPS 优先。
- 标准/严格两档指纹保护。
- 字幕轨、音轨选择。
- 多设备收藏与设备能力缓存。
- 可复现构建和 SBOM 发布。
- HarmonyOS ArkWeb 技术预览：基础浏览、用户播放识别、设备连接和投屏控制闭环。
- 多标签资料包、表格 CSV 导出、图片说明和本地收藏库。
- 只读 Agent Developer Preview：读取当前页、提取 Markdown、查询标签和投屏状态；默认关闭，只监听 loopback。
- 用户确认的播放队列；不从任意网站自动建立剧集库。
- 普通 DLNA/兼容接收端基础直投 Beta：仅当 Cast-SDK 明确支持，且只处理公开、无凭证、能力匹配的媒体。

### 6.3 P2 范围

- HarmonyOS 正式版（以前置技术验证和平台审核通过为条件）。
- 移动端遥控器。
- 多房间设备组，但不做向公众分享。
- 与内容方或平台官方投屏接口合作。
- 在明确授权场景下扩展高质量直投站点。
- 受控写操作 Agent：导航、标签管理、语义元素点击/输入和投屏控制；每类能力独立授权。
- 内容方授权的播放列表/课程/广告正片 Manifest；由内容方提供签名数据，接收端与 Cast-SDK 另立协议 Roadmap。
- 企业私有模型 endpoint、组织策略、审计导出和私有知识库连接器。

### 6.4 明确不做

- 视频下载、录制、离线缓存。
- 内容搜索、片库、榜单、推荐、线路聚合。
- 云端媒体代理、分享链接、跨用户转发。
- DRM 解密或许可证绕过。
- 广告屏蔽、快进、跳过。
- 批量账号、Cookie 导入导出、代理池、自动化养号。
- 任意可编程浏览器指纹模板。
- 无用户播放行为的后台全网嗅探。
- 从网页自动推断广告、正片或下一集并生成内容方 Manifest。
- 默认上传完整 DOM、隐藏节点、密码字段、表单值、Cookie、Authorization、浏览历史或原始网络响应。
- 暴露远程监听 MCP、原始 CDP/WebDriver、任意 JavaScript/RCE、任意文件读写或无确认支付/发帖/上传。
- 把模型输出当作 DRM、广告连续性、设备能力、权限或网络安全判断。

### 6.5 平台支持策略

| 平台 | 浏览器后端 | 产品定位 | 发布要求 |
|---|---|---|---|
| Windows 10/11 | CEF | 首个 Desktop Alpha/GA 目标 | 先通过完整功能、隐私、安全、签名和更新门禁 |
| macOS 12+ | CEF | 第二发布波次 | 复用共享契约，但独立通过 Apple Silicon/Intel、权限、公证和更新门禁 |
| 主流 Linux 发行版 | CEF | 支持清单驱动的 Beta | 先明确 Wayland/X11、PipeWire、发行版、GPU、打包和更新范围 |
| HarmonyOS | ArkUI/ArkWeb | 未来版本/技术预览 | ArkWeb 能力、NDK 共享核心、录屏/音频和应用市场审核均验证通过 |

“跨平台”不等于一份二进制包。产品需求、交互、协议和共享核心不按 Windows/macOS 拆分，但每个平台必须有独立的采集、编码、安全存储、权限、安装包和质量门禁。平台尚未通过门禁时，不得仅因其他平台已发布而宣称支持。

## 7. 核心体验

### 7.1 首次启动

1. 展示三个核心承诺：默认无痕、数据留在本机、只投自己的接收端。
2. 简明说明无痕边界：不保留本机记录，但网站、网络提供者仍可能看到访问行为。
3. 遥测默认关闭；用户可自愿开启匿名崩溃报告。
4. 提供“开始隐私浏览”和“创建常用空间”两个入口，默认突出隐私浏览。

### 7.2 浏览与播放

1. 用户在地址栏输入网址并访问。
2. 页面完整呈现，网站广告和交互不被修改。
3. 浏览器识别到媒体元素和网络候选，但不自动启动投屏。
4. 只有发生可信用户交互且媒体进入播放状态后，工具栏投屏按钮才高亮。
5. 多视频页面默认选择最近被用户操作、正在播放且可见面积最大的媒体。

### 7.3 投屏主流程

1. 用户点击工具栏“投屏”。
2. 浏览器展示当前媒体标题、当前进度和推荐投屏方式。
3. 用户选择自动发现的设备，或输入投屏码连接设备。
4. 策略引擎选择模式：
   - 满足高清直投门禁：推荐“高清直投”。
   - 不满足或无法确认：推荐“投当前标签页”。
5. 默认选择“从当前位置继续”。
6. 用户可展开选择“从头播放”；如果直投不能保证页面编排和广告连续性，则自动切换为标签页投屏或提示限制。
7. 接收端首帧出现后，浏览器显示遥控面板。
8. 用户停止、关闭标签页或会话超时后，媒体 relay token 立即失效。

### 7.4 投屏方式

| 模式 | 传输内容 | 优点 | 使用条件 |
|---|---|---|---|
| 标签页投屏 | 当前标签页画面与声音 | 保留页面、广告、字幕、弹幕和交互 | 默认兜底，未知站点优先 |
| 高清直投 | 接收端直接拉取 MP4/HLS/DASH | 清晰度高、低延迟、电脑负载低 | 通过 DRM、广告连续性、请求头、设备能力和协议门禁 |

### 7.5 广告连续性规则

- 不检测或操作“跳过广告”按钮。
- 不对广告视频修改 `currentTime`、播放速率或可见性。
- 不按广告域名过滤媒体候选。
- 服务端拼接广告随媒体流正常投送。
- 客户端广告与正片分离、无法在接收端复现播放器编排时，不允许以“从头高清直投”作为默认行为。
- 用户已经在电脑端看过广告，只能作为风险判断背景，不能作为“接收端必然保留广告”的技术结论。

### 7.6 网页内容提取主流程

1. 用户点击“整理当前页”，浏览器固定当前顶层标签和 navigation generation。
2. Renderer 只生成有大小、节点数和字段白名单的语义快照；密码、隐藏表单值、脚本、样式、Cookie、请求头和跨源 iframe 正文不进入快照。
3. Browser process 校验来源、前台标签、generation、消息大小和字段，再交给本地确定性内容管线。
4. 用户先看到正文、表格、链接、图片引用、代码块、脱敏来源、抓取时间和内容 hash 的预览；来源默认移除 query/fragment，完整当前 URL 只有用户在本机导出预览中主动选择才加入。
5. 用户可以复制 Markdown、保存到自己选择的位置，或生成本机阅读卡片。
6. 导航、标签关闭、Profile 销毁或用户取消会使旧快照和任务立即失效；迟到结果不得覆盖新页面。

确定性导出必须在没有模型、模型离线或模型调用失败时仍可使用。首期只保证当前顶层页面；跨源 iframe、需要滚动加载的完整站点和无限列表明确显示“未包含”，不得伪装成完整抓取。

### 7.7 AI 总结与问答主流程

1. 用户在提取预览中选择摘要、要点、大纲或问答。
2. 产品展示模型提供方、预计发送字段、内容长度、是否包含图片和本次保存策略；P0 不发送图片二进制或原始图片 URL。
3. 用户确认后，只发送经过本地清洗且与当前任务相关的 `PageSnapshot` 子集；不发送完整 URL query/fragment、浏览历史、Cookie、Authorization、隐藏 DOM 和其他标签内容。
4. 模型输出与来源快照绑定，显示“AI 生成”标识和可追溯引用；无法定位的结论不得显示为网页原文事实。
5. 超时、取消、额度不足、provider 错误或页面已导航时，任务收敛为明确失败，不影响本地 Markdown。

首期 provider 支持采用稳定接口 + Fake 建立契约；实际云端 provider 只有在平台安全存储、发送前预览、删除/轮换和隐私评审完成后才进入产品。P0/P1 只允许注册并版本化的 HTTPS provider origin，逐跳限制 redirect，Key 不得发往其他 origin；任意自定义/内网 endpoint 属于 P2 企业策略与独立 SSRF 门禁。默认 provider、BYOK、本地模型和企业 endpoint 是部署策略，不得改变数据最小化语义。

### 7.8 Agent 与 MCP 主流程

Agent 能力按风险拆分，而不是暴露一个“控制浏览器”总开关：

| 级别 | 示例 | 默认策略 |
|---|---|---|
| R0 本机状态 | 当前产品版本、能力清单、是否存在活动标签 | Developer Preview 可读取，不含页面内容 |
| R1 页面读取 | 当前页标题、选中文本、Markdown、标签列表 | 每任务授权；Profile 切换或 App 重启失效 |
| R2 导航与展示 | 打开 URL、切换标签、滚动、生成阅读卡片 | 展示目标域名/标签并确认；限制频率与数量 |
| R3 投屏与播放控制 | 发现设备、开始投屏、暂停、seek、停止 | 展示设备、媒体/标签和参数；新会话或设备变化重新确认 |
| R4 页面写操作 | 点击、输入、提交 | P2 Preview；只允许 Browser 发放的可见语义元素 handle |
| 永久禁止 | Cookie/凭证读取、密码/支付输入、文件上传、任意脚本/CDP、远程监听 | 不提供工具，不允许通过配置解锁 |

CLI 与 MCP 共用同一 tool registry、权限门禁、状态机和审计 receipt。MCP 默认关闭，只允许 loopback、短期高熵 session secret 和显式客户端授权；页面内容被标记为不可信数据，不能通过提示词或文本改变工具权限。每个命令带 tab/navigation/generation，支持取消、超时、幂等键和有界并发。

### 7.9 内容到大屏

- 文章：先生成本机阅读卡片/分页预览，再查询接收端能力；没有正式 document/card facade 时不得在浏览器仓库私造接收端 URL 或控制协议。
- 视频：继续走现有 Mirror/Direct/Relay 策略和用户播放门禁，AI 不能绕过策略结果。
- 播放队列：首期只接受用户显式添加或内容方授权的条目；每个条目重新执行 DRM、凭证、广告连续性和能力门禁。
- 普通兼容接收端：只提供 Cast-SDK 已公开的基础 URL 播放/控制能力，不承诺登录态媒体、标签页镜像、阅读卡片、队列同步或高级模板。
- 蜡笔接收端：高级阅读卡片、模板、队列与状态回传必须先在接收端/Cast-SDK 定义版本化 capability；浏览器只消费 facade。
- 内容方 Manifest：只接受合作方签名/授权输入，不从网页候选合成广告、正片、商品、弹幕或下一集关系。

## 8. 隐私产品设计

### 8.1 隐私会话

- 默认开启。
- 会话内 Cookie、缓存和站点存储可以正常工作。
- 关闭全部隐私窗口后清理历史、Cookie、缓存、LocalStorage、IndexedDB、Service Worker 数据和权限临时授权。
- 下载文件和用户主动保存的书签不会自动删除，操作前明确提示。
- 不参与浏览器账号同步。

### 8.2 常用空间

- 用户主动创建并命名，例如“家庭影音”。
- 每个空间具有独立 Cookie、缓存、权限和本地存储。
- 空间之间不得共享登录态。
- 敏感配置使用操作系统安全存储保护。
- 支持“一键销毁空间”。
- 不提供批量复制空间、批量导入 Cookie、批量代理或自动化控制。

### 8.3 防追踪与防指纹

标准模式：

- 常见跟踪器拦截。
- 第三方 Cookie 限制。
- 跨站存储隔离。
- 引用来源最小化。
- HTTPS 优先。
- 权限按站点管理。

严格模式：

- 在兼容性允许范围内限制 Canvas、WebGL、Audio、字体和硬件信息暴露。
- 统一而非为每个空间随机生成身份。
- 明确提示严格模式可能导致验证码、登录、播放器或支付异常。

禁止能力：

- 自定义任意 UA/显卡/时区/Canvas 指纹组合。
- 按账号制造稳定且不同的伪装身份。
- 网站风控绕过承诺。

### 8.4 数据处理矩阵

| 数据 | 默认存储 | 默认上传 | 生命周期 |
|---|---|---|---|
| 隐私会话历史 | 否 | 否 | 仅内存 |
| 隐私会话 Cookie/缓存 | 临时 | 否 | 关闭全部隐私窗口后删除 |
| 常用空间 Cookie | 本机 | 否 | 用户删除空间或过期 |
| 媒体候选 URL | 临时 | 否 | 投屏会话结束即删除 |
| 完整 Cookie/Authorization | 不进入投屏协议 | 否 | 浏览器内部按站点使用 |
| 页面语义快照 | 临时 | 否 | 导航、标签关闭、任务结束或 Profile 销毁即删除 |
| 用户导出的 Markdown/阅读卡片 | 用户选择后本机保存 | 否 | 用户管理；保存前展示路径和包含内容 |
| 模型输入 | 默认不保存 | 仅用户逐次确认后发给所选 provider | 请求完成/取消后释放；provider 生命周期另行说明 |
| 模型 API Key/endpoint credential | 本机安全存储 | 只发给对应 provider | 用户删除/轮换/Profile 销毁 |
| AI 输出 | 当前任务内；用户可主动保存 | 否 | 导航/任务结束释放或按用户选择保存 |
| Agent capability grant | 临时 | 否 | 单次/单任务/本次 App 会话；不跨 Profile |
| Agent action receipt | 本机有界、脱敏 | 否 | 可配置短期 TTL；不含正文、完整 URL query 或 secret |
| Cast-SDK 设备与连接快照 | 临时 | 否 | 刷新、断开或 App 退出后释放 |
| 六位投屏码 | 临时 | 否 | 完成连接、取消或输入被替换后释放 |
| 崩溃报告 | 否，需用户开启 | 用户开启后上传 | 按隐私政策 |
| 媒体内容 | 不缓存 | 否 | 仅局域网流式传输 |

## 9. 设备连接与控制

### 9.1 自动发现

- 设备发现、去重、过期和 route 选择全部由 Cast-SDK 负责。
- 列表展示 Cast-SDK 返回的设备名称、在线状态、协议和能力摘要。
- 浏览器不复制 mDNS、SSDP、UDP 或设备识别逻辑。

### 9.2 投屏码

- 浏览器把用户输入原样交给 Cast-SDK 的投屏码 API。
- Cast-SDK 负责解析设备地址、查找接收端并建立连接；浏览器不复制算法、端口池或 fallback。
- 成功、未找到、格式错误、取消和 route lost 映射为稳定产品状态。
- P0 不增加云端信令、设备身份认证、密钥交换或临时授权层。

### 9.3 设备管理

- 重命名设备。
- 查看能力：H.264/HEVC/AV1、AAC/EAC3、MP4/HLS/DASH、最高分辨率和 HDR。
- 主动断开并重新连接。
- 查看最近一次连接时间，但默认不保存播放历史。

## 10. 状态与错误设计

| 场景 | 用户提示 | 产品行为 |
|---|---|---|
| 尚未主动播放 | “请先在本页开始播放” | 禁用投屏 |
| 未发现设备 | “未找到蜡笔接收端，可输入投屏码” | 提供刷新和输入码 |
| DRM | “该内容受版权保护，暂不支持投屏” | 禁止直投和任何绕过 |
| 高清直投不安全 | “为保留完整页面体验，将投当前标签页” | 自动降级 |
| 编码不兼容 | “接收端不支持当前编码” | 尝试标签页投屏；不默认转码 |
| 流地址失效 | “媒体会话已失效，请在页面重新播放” | 清理 session |
| 网络中断 | “接收端连接中断，正在重连” | 有界重试，超时停止 |
| 隐私数据清理失败 | 明确告警并提供重试 | 不静默宣称已清理 |
| 平台缺少能力 | “当前系统暂不支持该模式，将使用兼容模式” | 按能力清单降级，不改变安全策略 |
| 本地网络权限未开启 | “请允许访问本地网络以发现接收端” | 提供系统设置指引和投屏码备选入口 |
| 网页可播放但受 DRM 保护 | “可在本机观看，该内容暂不支持投屏” | 浏览与投屏能力分离，不把网页播放失败误报为投屏限制 |
| 页面无法完整提取 | “已整理当前可见正文，部分嵌入或动态内容未包含” | 允许预览和局部导出，不宣称完整 |
| 页面已导航 | “页面已变化，请重新整理” | 丢弃旧 generation 结果 |
| 模型发送未确认 | “请先确认发送内容和模型提供方” | 不发起网络请求 |
| 模型超时/取消/额度不足 | 显示稳定原因与重试入口 | 保留本地 Markdown，不自动切换 provider |
| Agent 权限不足 | “此操作需要本次授权” | 展示目标和参数；拒绝执行 |
| 页面内容尝试诱导工具调用 | 不向用户复述为系统指令 | 标记不可信来源；不能扩大 grant 或跳过确认 |
| MCP 非 loopback/无有效 secret | 不建立会话 | 无网络副作用，记录有界安全计数 |

## 11. 功能验收标准

### 11.1 浏览器

- Windows、macOS、Linux 分别通过主流站点登录、跳转、输入法、字体、无障碍、iframe、音视频和下载基础兼容测试。
- 隐私窗口关闭后，自动化测试无法从新会话读取前一会话的历史、Cookie 和站点存储。
- 常用空间之间无法互读 Cookie 和站点存储。
- 同一站点在各支持平台上的隐私策略、权限默认值、媒体判断结果和用户提示保持一致。
- HarmonyOS 技术预览必须通过同一协议与隐私一致性测试；ArkWeb 缺失能力必须在产品能力清单中显式降级。

### 11.2 投屏

- 未发生用户主动播放时不得开始投屏。
- 自动发现和投屏码两条路径都必须通过 Cast-SDK facade 完成连接，不得由浏览器自行拼接协议。
- 标签页投屏 P95 首帧时间不超过 5 秒，局域网 P95 端到端延迟目标不超过 1.5 秒。
- 高清直投 P95 首帧时间不超过 4 秒。
- 连续播放 30 分钟无崩溃、无 session 泄露、无开放代理行为。
- 停止后 10 秒内，旧媒体 token 必须不可访问。
- DRM 内容不得产生可用直投 URL。
- 多网卡、IPv4/IPv6、VPN 开关、睡眠唤醒和网络切换后不得继续使用 Cast-SDK 已判定过期的 route 或会话。

### 11.3 隐私

- 默认遥测关闭。
- 投屏信令不得包含 Cookie、Authorization、浏览历史或完整页面正文。
- relay 不向局域网暴露通用提取 API 和任意 URL 代理。
- 所有隐私承诺具备自动化测试或可审计实现，不使用无法验证的营销描述。

### 11.4 内容与 AI

- 无模型配置、provider 离线或用户拒绝上传时，当前页 Markdown 仍可确定性生成、预览和本机导出。
- 页面快照有节点数、文本长度、嵌套深度、图片/链接/表格数量和总字节上限；超限时有确定性截断标记，不阻塞浏览器 UI。
- Markdown 对标题、段落、列表、链接、图片引用、表格、代码块和 Unicode 的本地 fixture 输出通过 golden test；不得包含密码字段、隐藏表单值、脚本、Cookie、Authorization 或跨源 iframe 正文。
- 导航、标签关闭、Profile 销毁、取消和超时后，旧内容/模型结果不能写入新页面；任务缓存和 secret 释放可验证。
- 每次模型调用的实际 provider、发送字段和保存策略与确认预览一致；不得包含完整 URL query/fragment 或原始图片 URL；Fake provider、超时、取消、配额、流式中断和错误响应均有测试。
- AI 输出明确标识并绑定来源 snapshot/hash；模型不得决定 DRM、广告、权限、设备能力或网络安全结论。
- 当前页提取目标：100 KB 清洗后正文的本地 P95 不超过 1 秒，过程不造成前台页面明显卡顿；实际预算在 CNT Roadmap 中用基准测试校准。

### 11.5 Agent/CLI/MCP

- CLI 与 MCP 只调用同一版本化 tool registry；不存在绕过 UI/runtime 状态机的第二套浏览器或 Cast 控制路径。
- MCP 默认关闭且只绑定 loopback；无 secret、错误 Profile、过期 generation、重放、超长输入、超并发和远程来源全部失败关闭。
- R1～R4 capability 分级可独立授予和撤销；页面文本、模型输出和工具结果不能生成或扩大 grant。
- 所有副作用操作在执行前展示目标对象、关键参数和影响；确认过期、目标改变或页面导航后必须重新确认。
- 不提供 Cookie/Authorization/密码/支付/文件上传/任意脚本/CDP 工具；Release 产物扫描零命中调试后门。
- Agent task 支持取消、超时、幂等、旧结果丢弃和 App/Profile/标签退出时逆序清理；队列、日志、receipt 和并发有界。
- 安全评审必须覆盖网页间接提示注入、跨 Profile 访问、SSRF、DNS rebinding、confused deputy、工具参数注入、重放和本机恶意客户端。

### 11.6 跨平台发布门禁

- 每个平台具备独立 CI 构建、签名/公证、SBOM、依赖漏洞扫描、升级与回滚测试。
- 浏览器内核安全更新进入稳定版后，目标 14 天内完成三桌面平台评估和发布；高危漏洞按应急流程加速。
- `CastPolicyEngine`、Cast-SDK facade、relay token、隐私清理和错误语义通过共享契约测试，平台实现不得自行改写。
- 标签页采集、系统音频、硬件编码、安全存储、休眠恢复和权限撤销分别通过平台原生测试。
- 若 H.264/AAC、Widevine/CDM 或其他专有组件的许可和分发条件未确认，对应能力不得进入发布包或营销承诺。

## 12. 成功指标

### 12.1 北极星指标

在 AI 内容 Beta 之前，北极星仍是：

> 用户主动发起的投屏会话中，接收端在 10 秒内成功出首帧并稳定播放 10 分钟的比例。

AI 内容 Beta 之后新增独立主指标，不与投屏成功率强行合成：

> 用户主动发起的“整理当前页”任务中，在 10 秒内得到可预览结果并完成复制、保存、问答或大屏展示之一的比例。

### 12.2 核心指标

- 投屏发起成功率。
- 首帧成功率与 P50/P95 时间。
- 10 分钟、30 分钟稳定播放率。
- 自动发现成功率、投屏码连接成功率。
- 高清直投命中率与降级率。
- DRM/失效/不兼容误判率。
- 崩溃率和隐私数据清理失败率。
- 用户主动开启匿名遥测的比例。
- Markdown 提取成功率、P50/P95 时间、用户手工修正率和“内容不完整”率。
- 模型发送确认率、取消率、provider 错误率、回答引用覆盖率；不统计原始问题与正文。
- 阅读卡片生成/投屏成功率和阅读会话完成率。
- Agent 工具成功率、确认拒绝率、权限不足率、取消率和过期结果丢弃率；不上传工具正文与完整参数。

统计原则：指标默认在本机计算；只有用户明确开启匿名遥测后上传聚合值，禁止上传完整 URL、页面标题和媒体地址。

## 13. 合规门禁

- 产品化代码移除全部广告过滤、快进和跳过行为。
- 不为 VIP、DRM、签名算法或反爬措施提供绕过实现。
- 不在产品中展示提取到的原始媒体 URL。
- relay 仅服务当前投屏会话和当前 Cast-SDK 连接 route。
- 不把媒体送入云端。
- 不做内容聚合或公开分享。
- 商业发布前由知识产权和隐私律师按最终代码、文案、站点策略和接收端协议复审。
- 法务复审未通过的站点不得进入高清直投允许列表。
- 建立编解码器与 CDM 许可清单；CEF/Chromium 开源许可不自动覆盖 H.264、AAC、Widevine 等专有组件的专利、授权和分发义务。
- 分别完成 Windows、macOS、Linux 与 HarmonyOS 的应用签名、自动更新、系统权限和应用市场规则审查。
- 页面正文、图片和模型输出涉及著作权与个人信息；默认只处理当前页、用户主动触发、短期内存数据，不做站点级批量抓取或公共内容库。
- 云端模型调用必须有单独的 provider 数据处理说明、跨境/地区评估、发送前预览、删除/轮换能力和隐私评审；未完成前只允许 Fake/本地开发接口。
- Agent/MCP 作为新的高权限本机控制面，在独立威胁模型、渗透测试和 Release surface 扫描完成前只能作为默认关闭的 Developer Preview。
- 普通 DLNA 兼容只通过 Cast-SDK facade；未证明设备识别、能力、route 和媒体授权语义前，不作为 P0 宣传能力。
- 内容方广告/正片/商品/下一集 Manifest 必须由内容方授权并在接收端/Cast-SDK 建独立版本化协议，不由网页观察器推断或拼装。

1. 桌面正式版采用 Windows 首个 Alpha、macOS 第二波、Linux Beta/支持清单后置，还是三平台同日 GA；建议共享架构并行、发布日期按门禁分波次。

4. 标签页投屏各平台优先采用浏览器采集还是原生窗口/标签页采集 + 硬件编码。
